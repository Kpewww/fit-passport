# 竞品与开源方案综合研究：2026-10-24

本报告建议优先验证“**日常穿着记录如何积累可信合身证据**”，而不是把 Fit Passport 改成另一个以生成图片为中心的衣橱。项目已有衣橱、照片／批量、搭配、待购、3D身体、透明规则、买后反馈；缺口主要是低摩擦日常使用、实际穿着事件、情境适用性和证据可携。它们是研究优先级，不是全市场用户需求的统计排名。

研究只读公开资料与固定提交源码，没有安装竞品、登录、上传私人照片、购买、运行模型或功能实测。厂商截图、演示与用户评论均保留证据类型。功能宣称不等于可用或准确；未发现不等于不存在。价格／许可截至2026-10-24、按各文档指定地区和计费单位。完整方法与访问缺口见[方法／来源账本](methods-and-sources-2026-10-24.md)。

## 3. 研究优先的十项用户需要

排序综合证据强度、与定位关系、已有可复用能力和实现风险；**不是问卷统计Top10**。每项实验阈值应在试验前约定，以下指标是建议，不是已取得结果。n指独立评论样本，不把厂商功能页当第二位用户。

| 优先／用户问题 | 证据及计数 | 已有能力 | 最小改进或新流程 | 风险／可测实验 |
|---|---|---|---|---|
| 1. 不想先录完几百件才得到价值 | WearWow上传失败/等待n=3；Stylebook历史建库负担至少2来源；Outfity素材库好评n=1。[国内](chinese-wardrobe-apps-2026-10-24.md)、[全球](global-wardrobe-apps-2026-10-24.md)原文 | 照片、URL、批量、已知合身样本已有 | 从3件常穿衣＋1次有用检查开始；逐项进度、失败重试、保留草稿 | 压缩输入不可丢证据；比较首次有效检查耗时、完成率、每件修正次数和重试重复项 |
| 2. 图片变美不能把鞋底、颜色和衣服改坏 | Outfity鞋底原图n=1；WearWow外观/识别失真n=3；Leffa输出抱怨2条但不同问题。[图像研究](virtual-tryon-and-cutout-2026-10-24.md) | 原照片／裁剪／编辑已有，自动抠图未见 | 原图为主资产，派生图单列、可撤销／修mask、失败退回原图 | 生成补全伪造尺寸；用有权素材评颜色/纹理/细带保留、修复成功率、原图恢复率 |
| 3. 每天告诉系统“实际穿了什么”，别把计划当事实 | Outfity发布图分refresh/plan/save；Libre Worn按钮、Wardrowbe事件源码；搭搭整理/搭配历史各n=3。[开源](open-source-wardrobes-2026-10-24.md) | composer/ComfortCheck已有，wear ledger没有 | Owned item ID的新wear event；计划与实际分开，可选“仍合身？”追加现有反馈 | 自动计数污染学习；量计划转实际确认率、一次记录操作量、重复/撤销、四周留存 |
| 4. 购物时理解“为什么这个码”和“哪里不知道” | 企业公开fit score/通用提示；True Fit易理解好评n=3，但无概率校准；Bold文档方向歧义。[企业](enterprise-sizing-2026-10-24.md) | 来源／规则／拒答／区域图已有 | 比较身体与该件衣物、已知样本和偏好；缺单位/图表则追问或拒答 | 置信数字伪精确；测用户区分实测/估计的比例、错误自信、拒答后补证据率，分冷启动 |
| 5. 建议符合天气、场合、洗涤和旅行中的真实可用衣物 | 搭搭温度季节不合n=3历史；Acloset推荐冷热跨来源；Whering Planner当前帮助。[天气](weather-commercial-licenses-2026-10-24.md) | composer和occasion文字已有 | 用户选城市/条件，锁一件，限定owned/可穿/packing候选，规则先筛 | 气象不等于个人冷热/尺码；测约束违规、替换次数、解释理解；离线手填fallback |
| 6. 买完回来一次就能改进下次，而不是再填长表 | True Fit/Fit Analytics交易闭环为厂商证据；项目pilot指南为内部设计，不虚构用户n。[基线](fit-passport-baseline-2026-10-24.md) | FitOutcome、保留/换码/退货、品牌偏移已有 | 在用户同意的时点问购买结果、实际尺码和原因，支持跳过/撤回 | 退货并非都因fit；量可判定购买样本、反馈率、原因缺失、前后留出集校准，不报小样本准确率 |
| 7. 一个实物有多张图和状态，但只能算一件 | 搭搭多图/状态、Stylebook洗涤借出、Indyx视图请求；次数n未充分去重，只作方向证据 | item/variant/folders/SavedItem已有 | 明确原图/背面/细节/实穿/生成共用ID；owned/wishlist/archived与availability分开 | 合并错物/重复穿次；测试导入去重、撤销、图关系保真、CPW零价/未知价/同日多穿边界 |
| 8. 我能带走记录，不被录入成本或停服锁住 | Doppl停用官方索引；Indyx客服收费CSV、Whering无自助导出帮助是功能证据，不是投诉票数 | [有限元数据导出、改密码与软停用已有](fit-passport-baseline-2026-10-24.md#10-导出与账号控制的精确源码边界)；非全量备份或硬删除 | 版本化JSON/CSV＋原图＋关系包，导入预览／冲突处理；单独说明注销与退订 | 导出泄露身体/他人图、专有天气权利；往返数据/图片/关系完整率、选择披露测试、删除范围验收 |
| 9. 不拍脸也能选码；上传前知道去哪和留多久 | Mira云链、Whering训练同意分层、Bold无图仍身体数据、企业TTL缺口；无足够用户n | 测量/衣物证据无需真人VTON图 | 身体照/衣图/邮件/chat分开用途同意，provider/地区/TTL/删除状态就地说明 | 把“本地”或“不训练Gmail”泛化；测试拒绝后主流程可完成、撤权传播与日志无图片/尺寸泄漏 |
| 10. 日常入口清楚、失败能恢复，不为新功能增加迷宫 | Doppl历史崩溃n=4、上传阻塞n=4，导航n=2弱；Outfity历史难找n=1；IndyxConnect多请求n未全计 | dashboard、refresh单件单问、composer已有 | 今日一项主行动，生成历史独立可检索，持续job状态、保留输入、键盘/按钮替代摇动 | 功能过载/伪完成；测任务成功、回退次数、恢复成功、辅助技术可达，重新量当前UI而非沿用旧控件数 |

验证应把“用户觉得好看”“理解推荐”“实际合身”“减少退货”分开。真实试穿结果、拒答、失败和低置信样本必须进入评测，不只选最佳图片。

## 4. 可建立的优势是假设，不是独占事实

| 假设 | 当前支撑 | 竞争约束 | 如何证伪／确认 |
|---|---|---|---|
| 消费者拥有的跨店合身证据比孤立购物问卷更可持续 | 已知衣物／个人偏好／结果模型；导出仅有限元数据 | True Fit跨品牌图谱；Agio草案也做可携，不能称唯一 | 不同店重复检查时减少输入，跨品牌留出集收益，真实导出迁移 |
| 可解释来源／缺失／拒答比通用漂亮图更可信 | 规则引擎、数据来源和估计置信上限 | Bold有区域描述，企业亦有confidence／Fit Cues | 解释能否改善判断而非造成过信；错误自信率/校准 |
| 二手具体衣物实测是有用入口 | 单件判断与身体／衣物分离 | 需卖家可靠测量，不能宣称无竞品 | 同衣实测复测误差、买后结果、卖家噪声条件下拒答质量 |
| 日常wear+fit变化形成个体记忆 | ComfortCheck／Outcome已有，事件账本可扩 | 衣橱对手也可能收comfort；反馈会过期 | 随机对照可选反馈，比较新反馈对后续保留集贡献及用户负担 |

Google已文档化原生Chrome入口，扩展本身不是护城河；企业有目录与交易网络，Fit Passport不能声称数据规模或准确率胜出。相对清晰的切入是**用户可检查、可修正、可携带的个人证据**，其价值仍需真实使用验证。

## 6. 天气与抠图：采购结论要保留限制

详尽对照、当日计费单位、缓存／署名／再分发见[天气专档](weather-commercial-licenses-2026-10-24.md)。决策摘要：
- Open-Meteo **数据CC BY4.0 ≠免费托管可商用**；商业应用走商业计划，服务器AGPL是第三层。
- 和风适合中国候选，但GeoAPI权利和天气缓存不同；按请求组计费、展示署名／sources，不把专有geo裸导出。
- WeatherAPI Free API可商用但须署名、缓存时限和用户不确定性说明；不能误读网站内容条款。
- MET开放数据但无付费SLA、需识别UA／缓存／流量协议；OpenWeather现价已核，适用衍生许可仍待澄清。
- 城市级、服务器key与cache、可手填、过期标记；不发身体／照片给天气方。

详尽许可链、技术、API价格／保留见[抠图与VTON专档](virtual-tryon-and-cutout-2026-10-24.md)。**不可用一个绿色“可商用”抹掉下列门槛**：

| 方案 | 研究建议 | 未解决门槛 |
|---|---|---|
| 官方BiRefNet | 抠图评估短名单，保原图／修正 | MIT代码/权重卡不是上游数据或人物权利保证；每checkpoint另审 |
| RMBG-2.0 | 公开权重不用于免费商业上线 | CC BY-NC；商业自托管协议或API另走，BRIA现行PDF全文未读 |
| IMG.LY | 浏览器私有处理可评估 | AGPL允许商用但有义务，闭源组合需许可判断；模型包另核 |
| rembg | CPU/GPU基线包装器 | MIT wrapper不覆盖全部ONNX；具体转换来源、许可、hash必备 |
| SAM2 | 交互修mask配套 | Apache不代表自动衣物语义解析／柔和alpha |
| FASHN1.5 | 后续窄自托管实验 | Apache核心，原管线SegFormer parser阻碍；无parser平铺仅静态可行推断 |
| Leffa | 保留研究对照 | MIT核心＋权重不清除Dress Code/OpenPose/底模权限 |
| OmniTry | 暂不普通商业自托管 | Apache LoRA不能覆盖FLUX Fill dev非生产限制 |
| 商业FASHN API | 明确预算／同意后可作成本对照 | API权不授自托管；元数据非零留存，成本按接受结果计 |
| IDM/Cat/OOT等 | 研究比较 | NC授权，免费beta不自动非商业；长尾未全面核验 |

没有模型benchmark、采购或法律清关。抠图较适合先试，不意味着风险为零；真人VTON应独立于尺码路线排期。

## 7. 证据完成度与剩余缺口

所有指定产品有定位／平台／价格、功能证据、截图或明确缺口、尺码、口碑、隐私；开源另有栈／许可／借鉴。已保留69张公开发布方资产及来源，非私人图。未取得历史Mira四张、Parsa录屏本地帧、Leffa交互UI、Chrome实际VTON、部分小型OSS UI；不制造替代截图。Bold Kids现有资产为家庭宣传照，真正Kids UI仍缺。

评论不足最明显：穿啥、Outfity、WearWow第三负主题、各Mira、Leffa、Fit Analytics、Bold及OSS；搭搭可形成历史3＋3但老样本。Doppl为镜像历史样本，部分n=2；全球App部分主题未能完整去重计数，不能宣称全达≥3。完整流程、精确导出、失败扣费、真实隐私删除、不同国家／OS rollout、真实合身与退货因果都没有验证。

下一轮如获授权，先选小规模真实任务测试与人工测量／购买pilot，不扩张成更多营销功能。此次只写文档，不改产品代码、schema、包、部署或生产配置。
